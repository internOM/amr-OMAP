## 1. 项目概述

本项目基于 ROS 2 实现了一套基于摄像头的自动导引车（AGV）系统。AGV 沿工厂地面上的彩色胶带线（绿色和红色）行驶，在两个永久货架站之间循环运输物料箱：

- **Store（仓库站）** — 装载站，AGV 在此取箱
- **CA-PP（生产站）** — 卸载站，AGV 在此放箱

AGV 在两站之间持续循环运行。车道选择、对接行为及安全响应均自动处理，并提供基于网页的操作员界面用于监控和手动干预。

> **说明：** 概述内容良好。建议补充一行硬件平台信息——使用的机器人底盘型号、计算平台（树莓派 + 基站PC）以及传感器型号（摄像头、激光雷达）。这是新团队成员首先需要了解的内容。

## 2. 系统架构

AGV 采用分布式 ROS 2 发布-订阅架构。各硬件组件将原始传感器数据发布到对应话题，核心逻辑节点（`webcam_line_follow.py`）订阅所有传感器数据，处理后发布速度指令。网页操作界面通过 `rosbridge_websocket` 连接。

### 节点通信映射表

| 话题 | 方向 | 类型 | 用途 |
|---|---|---|---|
| `/image_raw` | → 节点 | `sensor_msgs/Image` | 摄像头图像，用于线条检测 |
| `/scan` | → 节点 | `sensor_msgs/LaserScan` | 激光雷达障碍物检测 |
| `/rack_status` | → 节点 | `std_msgs/String` | ESP32 货架槽位占用状态 |
| `/agv/cmd_enable` | → 节点 | `std_msgs/Bool` | 启动 / 操作员确认 |
| `/agv/cmd_stop` | → 节点 | `std_msgs/Bool` | 紧急停止 |
| `/agv/cmd_mode` | → 节点 | `std_msgs/String` | 手动车道切换 |
| `/cmd_vel_agv` | 节点 → | `geometry_msgs/Twist` | 速度指令至 twist_mux |
| `/agv/state` | 节点 → | `std_msgs/String` | AGV 当前状态至界面 |
| `/agv/mode` | 节点 → | `std_msgs/String` | 当前车道模式至界面 |
| `/ui_heartbeat` | 双向 | `std_msgs/String` | 心跳延迟测量 |

### 速度优先级（twist_mux）

| 话题 | 优先级 | 超时时间 |
|---|---|---|
| `/cmd_vel_teleop` | 255 | 0.5秒 |
| `/cmd_vel_estop` | 100 | 0.5秒 |
| `/cmd_vel_agv` | 10 | 0.5秒 |

> **说明：** 通信映射表清晰完整。建议补充说明遥控切换机制——当操作员按下 GO 键时，界面停止发布 `/cmd_vel_teleop`，该话题在 twist_mux 中于 0.5 秒内超时，自动将控制权移交给 `/cmd_vel_agv`。这一机制不够直观，容易引起混淆。

## 4. 节点与组件

### `webcam_line_follow.py` — AGV 核心控制节点

系统核心控制器，将视觉处理、安全检测、货架传感器逻辑和电机控制整合为一个状态机。

**核心子系统：**

**视觉处理**
- 以约 10Hz 订阅 `/image_raw`
- 将每帧图像裁剪为位于 3/4 高度处、高度为 20 像素的追踪条带，以降低处理开销
- 将条带转换至 HSV 色彩空间，分别应用绿色和红色掩膜
- 通过图像矩（`m10 / m00`）计算线条质心

**PD 控制器**
- 误差 = 质心 X 坐标 − 图像中心（`w // 2`）
- P 项响应当前误差；D 项抑制振荡，确保平滑跟线
- 输出控制 `angular.z`；`linear.x` 由独立的斜率限制器管理
- 参数：`Kp = 0.0032`，`Kd = 0.00072`，`MAX_ANG_Z = 1.0`

**激光雷达分层安全系统**
- 四个安全区域，每个区域有独立的距离阈值和锥角
- 距离越近，锥角越窄，以减少侧面结构的误触发
- 需要连续 20 帧无障碍才判定路径畅通
- 畅通后等待 3 秒，再通过斜率限制器平滑加速恢复行驶

| 区域 | 距离 | 锥角 |
|---|---|---|
| 1 | 0–0.225 m | ±45° |
| 2 | 0.225–0.318 m | ±22.5° |
| 3 | 0.318–0.45 m | ±15° |
| 4 | 0.45–0.588 m | ±11.25° |

**货架传感器集成**
- 维护一个包含 Store 和 CA-PP 两站共 12 个槽位状态的字典
- 槽位编号：`Store-A1` 至 `Store-B3`，`CAPP-A1` 至 `CAPP-B3`
- 某列（A 或 B）中任意一个传感器读数为 `1`，则该列视为已占用
- 每次传感器数据更新后重新评估车道，并通过 `mode_callback` 无缝切换

> **说明：** 细节程度合适。激光雷达区域表中的数值可能与代码中 `SAFETY_TIERS` 的实际常量略有出入——发布说明文档前请核对确认。

### `rack_websocket_server.py` — ESP32 桥接节点

运行一个 WebSocket 服务器（默认端口 8000），接受货架上 ESP32 微控制器的连接，解析 JSON 数据并发布至 `/rack_status`。

**接收自 ESP32 的消息格式：**
```json
{ "rack_id": "CAPP-A1", "status": 1, "distance_cm": 4.2 }
```

**发布至 ROS 的消息格式：**
```
rack_id:status:distance_cm
例如："CAPP-A1:1:4.2"
```

每个 ESP32 内置防抖状态机（5 帧），在改变状态前过滤瞬间误读。

> **说明：** 内容良好。建议补充说明 ESP32 在运行中断线时的处理方式——节点会保留最后已知状态而非重置为 0。这是生产环境中的重要边缘情况，应明确记录。

### `agv_display.html` — 操作员控制界面

基于网页的控制面板，通过 `rosbridge_websocket`（端口 9090）连接 ROS，由 Python HTTP 服务器在端口 8080 提供服务。

**功能：**
- 实时 AGV 状态显示，配有颜色编码样式
- GO / STOP 按钮，分别发布至 `/agv/cmd_enable` 和 `/agv/cmd_stop`
- 车道模式切换按钮，发布至 `/agv/cmd_mode`
- 通过 `/ui_heartbeat` 往返测量显示网络延迟
- 带时间戳的滚动活动日志，记录状态转换事件
- 单会话强制机制（通过 `/ui_active_client`）——同一时间只允许一个浏览器标签页控制 AGV，第二个标签页连接时将终止第一个会话
- 自主运行期间显示摇杆锁定遮罩，通过 `/cmd_vel_teleop` 支持遥控操作

> **说明：** 单会话强制机制是重要的安全特性，应更清晰地说明——被踢出的会话会看到"会话已终止"页面并提供重新连接按钮。此外，活动日志章节提到监听 `/agv/state` 和 `/agv/mode`——应说明日志条目在状态**发生转换时**生成，而非每次 1Hz 心跳重播时生成，否则操作员可能会疑惑为何日志不持续更新。

## 5. 系统运行

### 前置条件
- 已安装并 source ROS 2 环境
- 已安装 `rosbridge_server` 软件包
- 已安装并配置 `twist_mux` 软件包

### 编译
```bash
cd ~/ros2_ws
colcon build --packages-select amr_ws --symlink-install
source ~/ros2_ws/install/setup.bash
```

### 树莓派端（硬件）
```bash
ros2 launch amr_ws bringup_launch.py
```

### 基站PC端（各终端）
```bash
# 终端 1 — AGV 核心节点
ros2 run amr_ws webcam_line_follow

# 终端 2 — 货架传感器桥接
ros2 run amr_ws rack_websocket_server

# 终端 3 — 网页界面 ROS 桥接
ros2 run rosbridge_server rosbridge_websocket --ros-args -p delay_between_messages:=0.0

# 终端 4 — 提供操作员界面服务
cd ~/ros2_ws/src/amr_ws/html && python3 -m http.server 8080
```

操作员在同一网络下的任意设备上访问 `http://<机器人IP>:8080/agv_display.html`。

> **说明：** 本章节内容实用但较为简略。强烈建议补充：（1）启动顺序说明——AGV 节点最好在摄像头和激光雷达驱动确认运行后再启动，否则会静默丢失早期帧；（2）rosbridge IP 依赖说明——`agv_display.html` 连接至 `window.location.hostname:9090`，因此 HTML 必须由运行 rosbridge 的同一台机器提供服务，否则需手动修改 IP；（3）关机流程——各终端按启动逆序依次按 Ctrl+C，对不熟悉 ROS 的操作员应明确说明。

## 6. AGV 操作逻辑

### 持续循环

AGV 在两站之间持续循环运行：

```
[Store — 装载] ──绿线──▶ [绿色爆炸阈值] ──▶ [U形转弯] ──▶ [对接1 — CA-PP卸载]
      ▲                                                              │
      └───────────────────────红线──── [对接2 — Store装载] ◀─────────┘
```

### 车道选择

车道根据实时货架传感器状态持续评估，每次传感器数据更新时重新应用。

**Store 站（绿色爆炸 — 装载）。前往有物料处，A 列优先：**

| store_A | store_B | 车道 |
|---|---|---|
| 0 | 0 | 停止 — 无可装载物料 |
| 0 | 1 | 红色车道 |
| 1 | 0 | 绿色车道 |
| 1 | 1 | 绿色车道 |

**CA-PP 站（红色爆炸 — 卸载）。避开已满列，默认绿色：**

| capp_A | capp_B | 车道 |
|---|---|---|
| 0 | 0 | 绿色车道 |
| 0 | 1 | 绿色车道 |
| 1 | 0 | 红色车道 |
| 1 | 1 | 停止 — 两列均已满 |

### 状态转换图

```
停止 ──GO──▶ 运行中 ──绿色爆炸──▶ U形转弯 ──▶ 对接1
               │                                   │
               │◀──────────────────────────────────┘（完成）
               │
               └──红色爆炸──▶ 对接2 ──▶ U形转弯 ──▶ 运行中
               │
               └──障碍物──▶ 检测到障碍 ──（清除）──▶ 运行中
               │
               └──货架已满──▶ 等待 — 无货架 ──（货架清空）──▶ 运行中
               │
               └──槽位阻塞──▶ 等待 — 请确认 ──（操作员按GO）──▶ 对接2 第3阶段
```

### 对接1 — CA-PP 卸载
由绿色爆炸触发，在 U 形转弯完成后进入。

| 阶段 | 动作 | 持续时间 |
|---|---|---|
| 1 | 使用 PD 原地对齐（linear.x = 0） | 直至误差 ≤ 10px |
| 2 | 倒退进入货架站 | 5 秒 |
| 3 | 保持静止 — 卸载 | 5 秒 |
| 完成 | 恢复运行中状态 | — |

### 对接2 — Store 装载
由红色爆炸直接触发。

| 阶段 | 动作 | 持续时间 |
|---|---|---|
| 1 | 倒退至定位点 | 1.5 秒 |
| 2 | 使用 PD 原地对齐 | 直至误差 ≤ 10px |
| 3 | 前进进入货架站 | 5 秒 |
| 4 | 保持静止 — 装载。**传感器门控：若槽位已占用，进入等待 — 请确认状态** | 5 秒 |
| 5 | 倒退退出 | 5 秒 |
| 完成 | 触发 U 形转弯 | — |

> **说明：** 对接表格清晰。需要指出一处待确认内容：根据已达成的设计摘要，传感器门控位于第 2 阶段与第 3 阶段之间（对齐完成后、前进之前），而非第 4 阶段期间。请在最终代码完成后核对并更新此处。此外，建议注明激光雷达障碍检测在对接和 U 形转弯期间**已禁用**，以防止货架结构引发误停。

## 7. 操作员界面参考

### 状态显示颜色说明

| 状态 | 颜色 | 含义 |
|---|---|---|
| 运行中 | 绿色 | 正在跟线行驶 |
| 已停止 | 红色 | 操作员手动停止 |
| 检测到障碍 | 红色 | 激光雷达阻塞 — 等待路径清空 |
| U形转弯 | 琥珀色 | 正在执行转向动作 |
| 对接1 / 对接2 | 紫色 | 对接协议执行中 |
| 等待 — 无货架 | 红色 | 当前站点无可用货架 |
| 等待 — 请确认 | 琥珀色 | 槽位传感器阻塞 — 按 GO 继续 |

### 按钮功能说明

| 按钮 | 话题 | 功能 |
|---|---|---|
| GO | `/agv/cmd_enable` | 启动跟线，或确认传感器门控 |
| STOP | `/agv/cmd_stop` | 立即停止 AGV |
| 模式切换 | `/agv/cmd_mode` | 手动切换绿色或红色车道 |

> **说明：** 参考表格清晰实用。建议补充说明手动模式切换会被货架传感器的自动车道选择逻辑覆盖——若操作员切换至红色车道，但传感器逻辑判断应走绿色，节点将在下一次传感器更新周期内自动切回。这对期望手动切换持久生效的操作员来说可能造成困惑。
